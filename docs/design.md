# 設計メモ

## 目的

セミナーのハンズオンで、参加者が次の2つをすぐにできるようにする。

- ワークで使う文章（プロンプト）を、打ち間違えずにコピーしてAIのチャットに貼る
- 事業所メモ（md ファイル）をダウンロードする、または自分で作る

## 想定する使う人

- AI や IT に慣れていない、福祉事業所のサービス管理責任者と職員
- 会場の共有パソコン（Windows）が中心。自分のスマホで見る人もいる
- 講師の画面を見ながら、同時にこのページを開く。迷子になると、講義についていけなくなる

## 設計の考え方

- 1画面で見ることを1つに絞る。ステップを1つずつ表示し、「次のステップへ」で進む。やること、コピーする文、確かめることの順に並べる
- いま何番目かが分かるようにする。上に「4 / 11」と進み具合の線を出す。番号を押せば、前後のステップにも飛べる。ブラウザの「戻る」でも前のステップに戻れる
- JavaScript が使えないときは、全ステップを縦に並べたままにする
- 「貼る」と「確かめる」を、見た目の構造で分ける。貼るステップにはコピーの枠があり、確かめるステップには枠がない。色で分けない
- 一番大きく目立たせるのは、コピーのボタンだけ。ほかは黒と灰色にする
- 押したら、必ず反応が分かるようにする。ボタンが黒くなり「コピーしました」と出る。失敗したときは文を選択して手で押せるようにする
- 専門用語を避ける。「プロンプト」ではなく「AIに送る文」と呼ぶ。md は初出でひとこと説明する
- 困ったときの逃げ道を、ページの中に置く。通信が弱い、コピーできない、ファイルを付けられない
- 実在の情報を入れないよう、各ページの先頭で伝える

## 見た目

- 色は、黒・灰・緑1色（講師の資料と同じ緑）。ボタンと、いま見ているステップだけに使う
- 区切りは、線と余白で見せる。色付きの枠、左の色帯、ピル型のラベル、影は使わない
- 文字は18px以上。スマホでも17px。行間は広め
- フォントは Noto Sans JP（可変フォント）。外部の配信元には頼らず、`assets/fonts/` に置いて読み込む。会場の通信が弱くても崩れず、閲覧の情報が外へ送られない。使う文字の分だけ読み込まれ、1ページあたり約560KB。ライセンスは SIL Open Font License 1.1（`assets/fonts/OFL-LICENSE.txt`）
- 見出しだけ、字間をつめる設定（`palt`）を使う
- ボタンは高さ48px以上。押す場所を大きくする
- 画面が狭いときは1列にし、ボタンを横いっぱいにする

## アクセシビリティ

- キーボードだけで、すべての操作ができる。フォーカスの輪郭を濃くする
- 「本文へ移動」のリンクを置く
- コピーの結果は、画面の表示と読み上げ（`aria-live`）の両方で知らせる
- 色だけで意味を伝えない。ステップの種類は文字（貼る／確かめる）でも書く
- 動きを減らす設定（`prefers-reduced-motion`）に従う

## 技術

- 静的なHTML、CSS、JavaScript。フレームワークとビルドは使わない
- コピーは `document.execCommand('copy')` を先に試し、だめなら Clipboard API を使う。どちらも失敗したら、文を選択状態にして手動のコピーを案内する
- ダウンロードは `<a download>`。ファイルの実体は ASCII の名前で置き、保存される名前は日本語にする
- 外部への通信は、「Gemini を開く」のリンクだけ。解析ツール、外部のフォント配信、外部スクリプトは使わない
- `noindex`。URL は参加者にだけ配る

## 公開の前に確かめること

- 本文の文が、講師の資料の文面と同じか
- `memo.html` の「ファイルの中身」が、`files/jigyosho-memo.md` と同じか
- 実在の名前、連絡先、診断、記録が入っていないか
- 会場の画面で、「コピー」が動くか。ダウンロードしたファイルが、AIのチャットに付けられるか
